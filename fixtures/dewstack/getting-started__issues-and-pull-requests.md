# Issues and pull requests

A repository is more than the files sitting in it. It also holds a record
of every problem anyone has reported and every change anyone has
proposed. Both are worth reading, since they are how this course itself
gets fixed.

## What a repository actually holds

Open [github.com/deweydex/dewstack](https://github.com/deweydex/dewstack)
and you are looking at this course's own repository, the kind of thing
your account page described. `tutorials/` holds every page you are
reading, `build.py` is the script that turns them into the site, and
`README.md` is the file GitHub shows first. Nothing here is hidden from
you.

## An issue is a report, filed in the open

Most pages on this site end with a line: "Something wrong on this page?
Tell us." Choose "It gives an error" or "The page is wrong, or I could
not follow it." GitHub opens a new issue in this repository, with the
page and its version already filled in. An issue is just that: one report,
with a title, a description, and a place for anyone to reply. Filing one
does not need permission from anyone. Reading one does not either —
[the open issues](https://github.com/deweydex/dewstack/issues) are
public, same as everything else here.

## A pull request is a proposed change

A pull request is a set of edits, sent to the repository for somebody to
review before it becomes part of it. [Pull request
#35](https://github.com/deweydex/dewstack/pull/35) is a real one: it
added the report line described above, and the sections you just read
about your username and GitHub Education. Opening it shows what a pull
request looks like: a diff (the exact lines that changed), a
conversation about them, and a decision at the end to accept it or ask
for changes first.
